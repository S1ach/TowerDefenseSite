# Sentinel — 3D Tower Defense

Браузерная игра на русском: 12 волн, три типа врагов и башен, строительство, улучшения, экономика, пауза, скорости 1×/2×/4×, сохранения, серверный рейтинг и наблюдение. Модели построены из примитивов, внешние 3D-ассеты не нужны.

## Быстрый запуск

Node.js 22.12+, npm. Для локальной игры сервер и база не нужны:

```sh
git clone https://github.com/S1ach/TowerDefenseSite.git
cd TowerDefenseSite
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. Выберите башню в арсенале, нажмите на свободное место рядом с дорогой и запустите волну. Выбранную башню можно улучшить, продать или настроить ей приоритет цели. Пробел переключает паузу, Esc отменяет строительство. Перетаскивание вращает камеру, колесо мыши и жест двумя пальцами меняют масштаб.

Для сохранения откройте кнопку с дискетой справа сверху. Сохраняться можно между волнами; загрузка требует подтверждения замены текущей игры. Локальный слот хранится в браузере и пропадёт при очистке данных сайта.

## Сервер и PostgreSQL

Скопируйте `.env.example` в `.env`, задайте свой `DATABASE_URL` и случайный `JWT_SECRET` длиной не менее 32 символов. Файл `.env` исключён из Git и не поставляется с репозиторием. Не используйте пример секрета. Для генерации можно выполнить `openssl rand -hex 32` и вставить результат в `.env`.

```sh
# Docker Desktop должен быть запущен
# Пароль в compose.yaml предназначен только для локальной разработки
docker compose -p sentinel-td up -d postgres
npm run db:generate
npm run db:migrate
npm run dev:all
```

Если Vite уже запущен, достаточно `npm run server`. API слушает `127.0.0.1:3001`; Vite проксирует `/api` и `/socket.io`. Используйте `127.0.0.1`, как в `CLIENT_ORIGIN`, а не альтернативное имя хоста.

Чтобы остановить базу без удаления сохранений: `docker compose -p sentinel-td stop`. Данные находятся в отдельном Docker volume. Для новых изменений схемы используйте `npm run db:dev -- --name название` и сохраняйте миграцию в Git.

Серверные функции находятся в окне «Сохранения и сеть». После регистрации доступны сохранение, список сессий, загрузка и выход. Нажатие «Сохранить на сервере» обновляет выбранную сессию; после новой игры создаётся новая сессия. В рейтинге отображаются последние сохранённые результаты сессий.

## Реализованные этапы

1. Vite, React, TypeScript, Canvas, свет, карта и ограниченная камера.
2. Модель врага и независимое от FPS движение по маршруту.
3. Настраиваемые волны и интервалы появления.
4. Автоматический выбор цели, таймеры стрельбы и попадания.
5. Строительство указателем, привязка к сетке, зелёный/красный предпросмотр.
6. Золото за убийства и волны, магазин и проверка стоимости.
7. Выбор, радиус атаки, характеристики, улучшения и продажа.
8. Пулемёт, пушка, снайпер; пехота, разведчики и танки.
9. Пауза, 1×/2×/4×, автоматический запуск волн, победа и поражение.
10. Поворот башен к цели, снаряды, индикаторы здоровья и частицы уничтожения.
11. Express, PostgreSQL/Prisma, вход, сохранения и рейтинг; Socket.IO для наблюдения.
12. Диагностика, InstancedMesh, пул снарядов, тесты и измеряемая нагрузка.

## Архитектура

```text
src/
  app/                 точка входа, стили, Redux Toolkit
  pages/game/          компоновка сцены и интерфейса
  widgets/
    game-world/        Three.js-представление, ввод указателя и мост симуляции
    game-hud/          магазин, выбранная башня, волны, диагностика
  features/session/    локальные/серверные сохранения и наблюдение
  shared/api/          HTTP-клиент
  game/
    core/              GameEngine, GameState, GameLoop, EventBus, схема сохранения
    systems/           движение, волны, выбор целей, бой, снаряды, экономика
    entities/          интерфейсы игровой модели
    config/            баланс и координаты карты
    math/              маршрут и проверка размещения
server/                Express, авторизация, маршруты, Socket.IO
prisma/                схема и миграции PostgreSQL
tests/                 тесты движка, API/Socket.IO и измерение нагрузки
```

Применена облегчённая Feature-Sliced-структура: отдельные каталоги появляются там, где есть самостоятельная ответственность. Мелкие команды магазина остаются рядом с HUD и вызывают публичный API движка. Пустые слои и дублирующие модели не добавлены.

**Поток данных:** ввод → методы GameEngine → состояние и игровые системы → события и отображение. Движок не импортирует React, Redux или Three.js. `SimulationDriver` передаёт прошедшее время движку, а компоненты сцены отображают результат.

**Redux:** два среза — `game` с кратким снимком игры и `settings` с выбором башни, режимом строительства и отладочными флагами. Снимок обновляется 10 раз в секунду. Авторитетное состояние врагов, снарядов и таймеров живёт в движке. Выделять шесть почти пустых Redux-срезов не нужно: волны, экономика и сущности уже разделены системами игрового домена. React не обновляет позиции сущностей через `setState` на каждом кадре.

## Важные игровые понятия

### Delta time и фиксированный шаг

Delta time — число секунд с предыдущего кадра. Перемещение равно `speed * delta`, поэтому скорость задаётся в единицах мира в секунду. `GameLoop` накапливает время и выполняет шаги по 0,05 секунды (20 Гц). В 30 и 144 FPS за одинаковое время выполняется одинаковая симуляция; это проверяется тестом сравнением полного состояния.

Скорость игры множит поступающее игровое время. Пауза не накапливает его. После возвращения из фоновой вкладки учитывается максимум 0,25 секунды за кадр: игра не пытается мгновенно проиграть пропущенные минуты. Визуальное положение врага интерполируется между двумя последними шагами — с задержкой до одного шага, зато без скачков.

### Указатель и строительство

R3F преобразует координаты указателя в луч камеры и находит пересечение с невидимой плоскостью земли. Это raycasting — определение объекта под курсором в 3D. Позиция привязывается к шагу 0,5. Проверки границ, дороги, пересечения башен и золота находятся в домене и повторяются при самом строительстве. Перетаскивание камеры не должно строить башни.

### Выбор целей и попадание

`TargetingSystem` перебирает живых врагов в радиусе. Доступны ближайший к базе, ближайший к башне, самый сильный и самый слабый. Это простой O(башни × враги) алгоритм: пространственный индекс стоит вводить по результатам измерений.

Боевой модуль создаёт снаряд после окончания перезарядки. `ProjectileSystem` двигает его с учётом времени и наносит урон при достижении цели. Если цель уже погибла или дошла до базы, снаряд исчезает. Пушка наносит одиночный урон; урон по площади не заявлен. Снайпер использует быстрый снаряд. Награда начисляется один раз при смерти.

### События и эффекты

EventBus передаёт `enemySpawned`, `enemyKilled`, `towerBuilt`, `towerUpgraded`, `towerSold`, `waveStarted`, `waveCompleted`, `baseDamaged`, `gameOver`, `shot`, `gameReset`. Частицы и сообщения подписываются на события; их отключение не меняет бой.

### Производительность

- Тела врагов, полоски здоровья, снаряды и частицы используют InstancedMesh: множество экземпляров одной геометрии рисуется небольшим числом вызовов отрисовки.
- Снаряды возвращаются в ограниченный пул вместо постоянного создания и удаления объектов.
- Позиции меняются через ссылки на Three.js-объекты, без React-рендера каждого врага.
- Установлены ограничение плотности пикселей 1,75 и одна карта теней 1024².
- R3F освобождает геометрии и материалы при размонтировании. Подписки, сетевые соединения и таймеры имеют очистку.
- Для динамических InstancedMesh отсечение целого меша отключено: его исходная ограничивающая сфера не соответствует движущимся экземплярам. Сцена маленькая и фиксированная. Для большой карты нужны разбиение на группы и обновление границ.
- LOD пока не нужен: модели состоят из малополигональных примитивов. GLTF можно подключить вместо `TowerModel`, сохранив доменный движок.

Кнопка с жуком показывает FPS, количество врагов, башен и снарядов, вызовы отрисовки, треугольники и заданную частоту симуляции. Можно показать путь, радиусы, зоны столкновений и остановить ИИ.

## Наблюдение

Сначала создайте серверное сохранение и нажмите «Транслировать игру». Передайте его код зрителю. Зритель вводит код в разделе «Наблюдение» другой вкладки. После закрытия диалога трансляция продолжается до остановки или закрытия игровой вкладки. Наблюдатель видит двумерную карту, башни, врагов и основные показатели; это отдельное представление того же состояния, без управления игрой.

Хост отправляет снимки 5 Гц, а сервер проверяет структуру, размер, частоту и принадлежность сессии. Позиции на карте зрителя плавно приближаются к последнему снимку. В сеть не передаются меши, материалы и состояние каждого кадра. Для дальнейшего масштабирования можно отправлять события строительства и убийств между более редкими опорными снимками. Текущий JSON-трафик растёт линейно с количеством врагов. При разрыве соединения UI сообщает об этом; трансляцию или просмотр нужно включить снова.

## API

Маршруты доступны на сервере напрямую и через префикс `/api` у Vite:

- `POST /auth/register` — имя, email, пароль от 8 символов.
- `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`.
- `GET /games`, `POST /games` — список и создание сохранения.
- `GET /games/:id`, `POST /games/:id/save` — загрузка и обновление своей сессии.
- `GET /leaderboard`, `GET /health`.

Пароли хешируются scrypt со случайной солью; JWT хранится в HttpOnly/SameSite-cookie и действует 2 часа. В production требуется HTTPS для Secure-cookie. Есть ограничение попыток входа, проверка Origin для браузерных записей, ограничение тела запроса, Zod-валидация и проверка владельца. Обновление сессии, башен и результата выполняется транзакцией. API и база по умолчанию доступны только локально.

Сохранение содержит версию формата, завершённую волну, золото, здоровье базы, счёт, убийства, позиции, типы, уровни и приоритеты башен. Снимки анимации не сохраняются.

**Практические ограничения:** рейтинг учебный, поскольку клиент вычисляет бой и может подменить допустимый по форме счёт. Для соревновательного рейтинга нужна авторитетная серверная симуляция или проверка повторов. Реестр трансляций и ограничение запросов находятся в памяти одного процесса. Нет восстановления пароля, миграции старых форматов сохранений и распределённого сервера. Проект подготовлен для локального портфолио и дальнейшего развития, а не публичного сервиса с недоверенными игроками.

## Проверки

```sh
npm run build              # строгая типизация клиента, сервера и тестов + Vite
npm test                   # автономные тесты движка
npm run test:integration   # нужны работающие API и PostgreSQL
npm run benchmark          # CPU-стоимость шага при 100/300/500 врагах
```

Интеграционная проверка создаёт временные аккаунты в локальной базе и удаляет только собственные данные после выполнения. Проверяет регистрацию, вход, сохранение/загрузку, неверные данные, чужой Origin, доступ к чужой сессии, рейтинг, запуск/просмотр/остановку трансляции.

Ручной сценарий:

1. Постройте пулемёт и снайпера. Попробуйте дорогу, край карты и место рядом с башней.
2. Выберите башню, проверьте радиус, улучшение, приоритет и стоимость продажи.
3. Запустите волну, переключите 1×/2×/4× и паузу. Враги должны идти по дороге, башни — поворачиваться и стрелять.
4. Дождитесь окончания волны. Проверьте награду, локальное сохранение и восстановление.
5. Войдите в аккаунт, сохраните на сервер и загрузите. Откройте трансляцию в другой вкладке.
6. Оставьте базу без защиты для проверки поражения. Победа наступает после 12-й волны.
7. Проверьте узкое окно, мышь и сенсорный ввод. Включите диагностику и сравните показатели до/после увеличения количества сущностей.

Частые ошибки: использовать кадры вместо секунд, наносить урон из визуального компонента, начислять награду повторно, доверять только цвету предпросмотра при размещении, сохранять незавершённый бой частично, обновлять Redux на каждом кадре, забывать очистку таймеров и считать клиентский рейтинг защищённым от подмены.
